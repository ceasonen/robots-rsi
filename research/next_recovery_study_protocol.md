# 下一阶段有限验证协议（提案，不是冻结注册）

创建日期：2026-11-04。目的：为“可学习性驱动的纠错生成”寻找能证伪的最小实验，而不是通过调整参数制造正例。

### A. 资格验证：能否让冻结学生接续？

- **对象**：历史 teacher 的 4 个确认成功上下文 × `parent, oldA_KL, coverage_KL` 三个冻结 actor × 自身完整前缀 / 严格重放 teacher 前缀 = 24 条开发回合。
- **必须先准备**：teacher 前缀每步动作、仿真/控制器完整状态与原始观测；3 个真实 checkpoint；语言条件下的真实历史 1..10；动作采样/模型随机种子。
- **端点**：绝对 520 步完整任务成功，900 步同轨迹延长仅辅助；teacher 前缀占实际控制/查询成本。
- **核验**：重放逐步比对物理状态、机器人状态、RGB/本体观测及 warning。不可仅用 `set_sim_state` 假称重放等价。
- **判据**：相同上下文老师前缀至少出现 2 个相对自身前缀的 520 步修复且无反向伤害，仅为描述性正信号。若连老师前缀后学生都不能成功，停止把“前缀分布偏移”作为主要原因；换有原子技能的 parent。
- **现状**：公开 GitHub 审阅快照缺 checkpoint 和教师原始全轨迹；目前未启动该 24 回合。若资源不可取得，需从公开可下载模型/任务重建独立实验，不得伪造原历史权重。

### B. 机制验证：纠错“能救场”和“能教会”是否不同？

对每个预注册失败前缀，用同一初态/阶段/绝对时钟产生 2–3 种教师干预：短退让、完整复位、可观察阶段再入（需真实可执行，避免使用训练学生看不到的特权输入）。优先筛选在教师侧**匹配成功率**的方案；教师失败同样保留。

分别测：
1. 有教师协助的完整任务成功；
2. 同前缀冻结学生接手续做成功；
3. 用该类示范更新后，教师完全撤掉，学生从新初态完整成功；
4. 对旧任务的 harm，干预步数、标签数、student 优化步、验证查询、wall。

要求不同学生/任务组合上出现**可重复可预测的教法差异**，而不是仅更强教师在当前 episode 更快。

### C. 反馈机制与对照

- 研究机制仅能使用**开发集**学生学习进展决定下一批纠错生成参数。冻结实验后才开放最终留出测试。
- 对照：最佳固定纠错生成、随机、反馈打乱、相同数据的普通 BC、全局 BC+KL、LRS 式示范延长、CUPID 式示范选择、SITT 式学生可模仿教师训练的可行适配（显式声明非完整复现）。
- 保持总预算（示范物理步、学生动作标签、优化步、筛选/验证查询）可审计；teacher 和 student 不共享会泄漏答案的特权标签。
- 主分析：逐任务簇汇总 repair/harm、相对 parent 的成功率变化及交互开销，多训练 seed；不把每个动作步当独立样本。
- **停止条件**：真反馈不胜打乱反馈 → 撤下“反馈学会生成”解释；不胜最强固定教法 → 不主张该机制有必要；新能力为 0 或 harm 不可接受 → 回到原子技能/局部监督基线。
